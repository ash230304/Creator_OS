1. Product Requirements

Create:

docs/PRD.md

Use this structure.

CreatorOS V1 — Product Requirements Document
1.1 Product Definition

CreatorOS is an AI-powered content creation and repurposing platform that transforms a creator's idea into a structured video script and converts uploaded long-form footage into short, captioned clips.

1.2 Target User

Primary user:

Individual content creators who create short-form video content such as Instagram Reels, YouTube Shorts, and TikTok videos.

1.3 Problem

Creators currently need multiple tools to:

Think of idea
   ↓
Write script
   ↓
Plan shots
   ↓
Record
   ↓
Transcribe
   ↓
Find highlights
   ↓
Edit
   ↓
Add captions

CreatorOS combines the core workflow into one system.

1.4 Core User Journey
1. User signs in
2. Creates project
3. Enters content idea
4. CreatorOS generates script
5. User records/uploads video
6. CreatorOS processes video
7. Video is transcribed
8. System identifies potential clips
9. FFmpeg generates clips
10. Captions are added
11. User views/downloads clips
1.5 Functional Requirements
Authentication
User can register.
User can log in.
User can authenticate using JWT.
User can access only their own projects/videos/clips.
Project Management
User can create projects.
User can view projects.
User can view project details.
User can delete projects.
Script Generation

Input:

Idea
Platform
Target duration
Tone

Output:

Hook
Script sections
Dialogue
B-roll suggestions
Shot suggestions
Editing instructions
CTA
Video Processing

System must:

Accept video upload.
Store video.
Create processing job.
Extract audio.
Generate transcript.
Detect potential highlights.
Generate clips.
Generate captions.
Store processed outputs.
2. Non-Functional Requirements

This part is often ignored by students. Don't ignore it.

Performance
API responses should generally return within a few seconds.
Long-running video processing must be asynchronous.
Upload/processing should not block API threads.
Security
Passwords must never be stored in plaintext.
JWT authentication.
Users can access only resources they own.
Validate uploaded files.
Restrict allowed video formats.
Reliability

Processing failures should produce:

PROCESSING
     ↓
FAILED

rather than crashing the application.

Maintainability
Layered architecture.
Modular packages.
DTOs rather than exposing entities directly.
Centralized exception handling.
Environment-based configuration.
Cost

V1 should prioritize:

Open-source models
Local processing
Free-tier infrastructure
Provider abstraction for AI

Critical architecture principle

The frontend never talks directly to PostgreSQL, FFmpeg, Whisper, or the LLM.

Everything goes through your backend.

Frontend
   ↓
REST API
   ↓
Spring Boot
   ↓
Services
   ↓
External/Infrastructure

That's your system boundary.

And you should be able to explain this in 60 seconds:

“CreatorOS is a backend-first AI content repurposing platform. A creator provides an idea, the system generates a structured script with production instructions, and after video upload, an asynchronous processing pipeline transcribes the video, identifies highlights, generates clips using FFmpeg, and adds captions. The core backend is a modular Spring Boot application backed by PostgreSQL, with AI and video-processing components isolated behind service abstractions. V1 deliberately avoids microservices and Kafka to keep the system cheap and maintainable while preserving clear processing boundaries for future scaling.”
